# Glossary

Quick reference for all terms used in this guide. For full explanations, follow the deep-dive links.

| Term | Definition | Deep Dive |
|------|-----------|-----------|
| Activation Function | A non-linear function applied after each layer's weight multiplication; without it, stacking layers provides no benefit over a single layer. Examples: ReLU, GELU, SiLU. | [Neural Networks](01-foundations/02-neural-networks.md) |
| Attention | A mechanism where each element in a sequence computes a weighted sum over all other elements, where the weights are learned based on content relevance. | [Attention](01-foundations/06-attention.md) |
| Attention Head | One of H parallel attention operations in multi-head attention, each with its own W_Q, W_K, W_V projection matrices. | [Attention](01-foundations/06-attention.md) |
| Attention Score | The dot product of a query with a key, measuring relevance between two tokens; divided by sqrt(d_k) before softmax. | [Attention](01-foundations/06-attention.md) |
| Autoencoder | A neural network with a bottleneck architecture that learns to compress input into a latent and reconstruct it; trained by minimizing reconstruction loss. | [Latent Space](01-foundations/07-latent-space.md) |
| AWQ (Activation-Weighted Quantization) | A PTQ algorithm that identifies salient weights using activation statistics and scales the weight distribution before quantization to protect them. Produces strong 4-bit accuracy. | [Quantization](01-foundations/10-quantization.md) |
| Axis / Dimension | A single "direction" in a tensor; a tensor's rank is the number of axes it has. | [Tensors](01-foundations/01-tensors.md) |
| Backward Pass (Backpropagation) | The computation of gradients by applying the chain rule backward through each layer; happens only during training. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Batch | A subset of the training data processed together in a single forward+backward pass; batching is more computationally efficient than processing one example at a time. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| BF16 (bfloat16) | "Brain float 16." 16-bit floating point with the same exponent range as float32 but reduced mantissa precision. 2 bytes per value. MLX's default dtype; preferred for training because it handles large gradients without overflow. | [Quantization](01-foundations/10-quantization.md) |
| Bias | A learned offset vector added after the weight multiplication; allows the layer to shift its output. | [Neural Networks](01-foundations/02-neural-networks.md) |
| BOS (Beginning of Sequence) | Special token prepended to indicate the start of a new input sequence; tells the model where the text begins. | [Tokenization](01-foundations/09-tokenization.md) |
| BPE (Byte-Pair Encoding) | The dominant subword tokenization algorithm; starts with characters, iteratively merges the most frequent adjacent pairs until the target vocabulary size is reached. | [Tokenization](01-foundations/09-tokenization.md) |
| Broadcasting | A set of rules for automatically expanding tensors with compatible but mismatched shapes during element-wise operations. | [Tensors](01-foundations/01-tensors.md) |
| CFG (Classifier-Free Guidance) | A technique that runs the model with and without conditioning at each step, then amplifies the difference; makes output more faithful to the prompt at the cost of 2x compute. | [Diffusion](01-foundations/08-diffusion.md) |
| Checkpoint | A saved snapshot of a model's weights at a particular point during training; loading a checkpoint is how pretrained models are distributed and how inference pipelines begin. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| CLIP Tokenizer | A BPE tokenizer with 49,408-token vocabulary and a hard 77-token context limit; used in Stable Diffusion 1.x and 2.x for text conditioning. | [Tokenization](01-foundations/09-tokenization.md) |
| Conditioning | External information (text, image, depth map) provided to the denoising model to guide what it generates; fed in via cross-attention. | [Diffusion](01-foundations/08-diffusion.md) |
| Context Window | The maximum number of tokens a model can process in a single forward pass; determined at training time; inputs longer than this limit are truncated. | [Tokenization](01-foundations/09-tokenization.md) |
| Contiguous | A tensor whose elements are stored in a single unbroken block of memory in the expected order; required by some operations. | [Tensors](01-foundations/01-tensors.md) |
| Convolution | A layer that applies a sliding kernel across a spatial input; efficient for images because the same weights are reused at every position. | [Neural Networks](01-foundations/02-neural-networks.md) |
| CPU | Central Processing Unit; the main processor with a small number of powerful, general-purpose cores optimized for sequential, logic-heavy work. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Cross-Attention | Attention where Q comes from one sequence and K, V come from a different sequence; used to let one modality guide another (e.g., text guiding video). | [Attention](01-foundations/06-attention.md) |
| CUDA | Compute Unified Device Architecture. NVIDIA's parallel computing platform and programming model for their GPUs. The dominant ML computing environment for research and production. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| DDIM | Denoising Diffusion Implicit Models; deterministic; uses the same trained model as DDPM but with a step-skipping formula; enables quality generation in 50-100 steps. | [Diffusion](01-foundations/08-diffusion.md) |
| DDPM | Denoising Diffusion Probabilistic Models; the original formulation; stochastic, requires many steps (typically 1000). | [Diffusion](01-foundations/08-diffusion.md) |
| Decoder | The neural network component that maps a latent representation back to high-dimensional output (pixels); the inverse of the encoder. Also, the transformer component that generates an output sequence. | [Latent Space](01-foundations/07-latent-space.md) |
| Denoising | The core diffusion operation: given a noisy input and its noise level, predict and remove the noise; the skill a diffusion model is trained to perform. | [Diffusion](01-foundations/08-diffusion.md) |
| Dequantization | The operation of converting quantized integer weights back to approximate float values at inference time, by multiplying the stored integer by the stored scale factor. | [Quantization](01-foundations/10-quantization.md) |
| Diffusion | A class of generative models that learn to reverse a noise-addition process; generate data by iteratively denoising random noise. | [Diffusion](01-foundations/08-diffusion.md) |
| DiT (Diffusion Transformer) | A transformer-based architecture for diffusion models; operates on flattened patches of the latent; used in Flux, SD3, LTX-Video. | [Diffusion](01-foundations/08-diffusion.md) |
| DPM-Solver | A higher-order ODE solver for diffusion; fewer steps needed for comparable quality (10-20 steps); common in production pipelines. | [Diffusion](01-foundations/08-diffusion.md) |
| Dtype | The numeric format used to store each element; determines precision and memory cost (e.g., float32, float16, int8). | [Tensors](01-foundations/01-tensors.md) |
| Embedding | A layer that converts integer indices into dense learned vectors via a lookup table; used to represent tokens, positions, or any categorical input. | [Neural Networks](01-foundations/02-neural-networks.md) |
| Encoder | The neural network component that maps high-dimensional input data (pixels) to a compact latent representation. Also, the transformer component that reads an input sequence and produces a contextual representation. | [Latent Space](01-foundations/07-latent-space.md) |
| EOS (End of Sequence) | Special token indicating end of input or output; the model generates this token to signal it has finished. | [Tokenization](01-foundations/09-tokenization.md) |
| Epoch | One complete pass through the entire training dataset. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Euler Scheduler | A simple ODE solver for diffusion; treats denoising as numerical integration of an ODE; fast and widely used. | [Diffusion](01-foundations/08-diffusion.md) |
| Feed-Forward Network (FFN/MLP) | The two-layer MLP inside each transformer block, applied identically to each position; expands dimension by ~4x, applies activation, then contracts back. | [Transformers](01-foundations/05-transformers.md) |
| Flash Attention | An IO-efficient attention algorithm (Dao et al., 2022) that tiles the attention computation to avoid writing the full seq-by-seq matrix to GPU memory. | [Attention](01-foundations/06-attention.md) |
| Flow Matching | A training and sampling approach that learns straight-line paths from noise to data; the model predicts velocity instead of noise; used in Flux, SD3, LTX-Video. | [Diffusion](01-foundations/08-diffusion.md) |
| Forward Pass | The computation of passing an input through all layers in sequence to produce an output; happens in both training and inference. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Forward Process | The training-time procedure of progressively adding Gaussian noise to clean data over T timesteps until it becomes pure noise; defined by a fixed mathematical formula, not learned. | [Diffusion](01-foundations/08-diffusion.md) |
| FP16 (float16) | 16-bit floating point. 2 bytes per value. Reduced range (max ~65,000); higher precision near zero than bfloat16. Common in CUDA inference. | [Quantization](01-foundations/10-quantization.md) |
| FP32 (float32) | 32-bit floating point. The standard precision for training. 4 bytes per value. Full range and precision, but expensive in memory. | [Quantization](01-foundations/10-quantization.md) |
| GGUF | A file format from llama.cpp that packages model weights, tokenizer, and metadata into a single portable file. Not a quantization algorithm; embeds the quantization scheme in the filename (e.g., Q4_K_M). | [Quantization](01-foundations/10-quantization.md) |
| GPU | Graphics Processing Unit; a processor with thousands of simple cores designed to run the same operation on many data elements simultaneously. Originally for rendering graphics, now essential for ML. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| GPTQ | A PTQ algorithm that uses second-order (Hessian) information to minimize output error when quantizing, layer by layer. Better accuracy than naive rounding at 4-bit. | [Quantization](01-foundations/10-quantization.md) |
| Gradient | For a given weight, the gradient is the rate of change of the loss with respect to that weight -- how much the loss would change if the weight changed by a tiny amount. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Gradient Descent | The optimization algorithm that updates each weight in the direction that reduces the loss, scaled by the learning rate. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Group Size | The number of consecutive weights that share a single scale factor in group quantization. Smaller group size means more scales, better accuracy, and slightly more memory overhead. Common values: 32, 64, 128. | [Quantization](01-foundations/10-quantization.md) |
| Grouped-Query Attention (GQA) | Multi-head attention variant where K and V heads are shared across groups of Q heads; reduces KV-cache memory with minimal quality loss. | [Attention](01-foundations/06-attention.md) |
| Hyperparameter | A design choice made before training that is not learned from data; examples include learning rate, number of layers, and layer width. | [Neural Networks](01-foundations/02-neural-networks.md) |
| Inference | Running a trained model on new inputs to produce predictions; weights stay fixed, no gradients are computed. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| INT4 | 4-bit integer. 0.5 bytes per value, 16 possible levels. Standard for aggressive LLM quantization; the practical lower limit before quality degrades significantly. | [Quantization](01-foundations/10-quantization.md) |
| INT8 | 8-bit integer. 1 byte per value, 256 possible levels. Requires a scale factor to map the integer range to the float range. Common for inference quantization. | [Quantization](01-foundations/10-quantization.md) |
| Kernel | A function compiled to run directly on GPU hardware, executed by thousands of threads simultaneously. Every ML operation (matmul, ReLU, attention) is backed by one or more kernels. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Kernel Fusion | Combining multiple GPU operations into a single kernel to reduce memory bandwidth; fused kernels keep intermediate values in fast registers instead of reading/writing to global memory between operations. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Key (K) | The "what do I contain?" vector; each token's key is matched against all queries, determining how much other tokens attend to it. | [Attention](01-foundations/06-attention.md) |
| KL Divergence | In VAEs, a regularization term that pushes the learned latent distributions toward a standard normal; what makes the latent space organized and sample-able. | [Latent Space](01-foundations/07-latent-space.md) |
| KV-Cache | Stored K and V tensors from previous generation steps, enabling efficient autoregressive generation by avoiding recomputation. | [Attention](01-foundations/06-attention.md) |
| Latent | A specific point or vector in latent space; the encoded representation of a single input (image, video, etc.). | [Latent Space](01-foundations/07-latent-space.md) |
| Latent Diffusion | The technique of running the diffusion process in latent space rather than pixel space; enables image/video generation at practical computational cost. | [Latent Space](01-foundations/07-latent-space.md) |
| Latent Dimensions | The shape of the latent tensor; for image models typically (H/8 x W/8 x 4) or similar; for video models adds a temporal dimension. | [Latent Space](01-foundations/07-latent-space.md) |
| Latent Space | The compressed, lower-dimensional space in which an encoder represents input data; semantically meaningful: nearby points represent similar inputs. | [Latent Space](01-foundations/07-latent-space.md) |
| Layer | A single mathematical transformation within a neural network; takes a tensor in, produces a tensor out. | [Neural Networks](01-foundations/02-neural-networks.md) |
| Layer Stacking | The practice of repeating identical transformer blocks in sequence; depth (number of blocks) is a primary driver of model capability. | [Transformers](01-foundations/05-transformers.md) |
| Lazy Evaluation | MLX's execution model: operations are not run immediately when called. Instead, MLX builds a computation graph and defers execution until forced (e.g., by mx.eval()). Enables kernel fusion. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Learning Rate | A hyperparameter that controls how large a step to take when updating weights; too large causes instability, too small causes slow training. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Linear Layer | A layer that performs output = input @ weight + bias; the most fundamental layer type (also called Dense or Fully Connected). | [Neural Networks](01-foundations/02-neural-networks.md) |
| Loss Function | A formula that measures how wrong the model's output is compared to the correct answer; produces a single scalar value that training tries to minimize. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Matrix | A 2-dimensional tensor; a grid of numbers arranged in rows and columns. | [Tensors](01-foundations/01-tensors.md) |
| Memory Bandwidth | The rate at which data can be moved between memory and the GPU's compute units, measured in GB/s. Often the real performance bottleneck for ML operations, not raw compute speed. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Metal | Apple's GPU programming API and shading language. The equivalent of CUDA for Apple GPUs. MLX abstracts over Metal so you don't need to write Metal kernels for standard operations. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Mixed Precision | Using different bit widths for different layers in the same model. Typically: attention and FFN layers at 4-bit; embedding, normalization, and output layers at float16. | [Quantization](01-foundations/10-quantization.md) |
| Model | A specific layer architecture combined with a specific set of trained parameter values. | [Neural Networks](01-foundations/02-neural-networks.md) |
| Multi-Head Attention | Running H independent attention operations in parallel, each with different projections; the heads' outputs are concatenated and projected back to d_model. | [Attention](01-foundations/06-attention.md) |
| Noise Prediction | The DDPM/DDIM model output mode: predict the noise that was added to the input (also called "epsilon prediction"). | [Diffusion](01-foundations/08-diffusion.md) |
| Noise Schedule | The sequence of noise levels (betas or alphas) used across timesteps; defines how quickly the signal is corrupted in the forward process and recovered in the reverse. | [Diffusion](01-foundations/08-diffusion.md) |
| Normalization | A layer that rescales activations to have controlled magnitude; prevents values from exploding or vanishing as they pass through many layers (e.g., LayerNorm, RMSNorm). | [Neural Networks](01-foundations/02-neural-networks.md) |
| Optimizer | An algorithm for computing weight updates from gradients; common optimizers (Adam, AdamW, SGD) use momentum and adaptive step sizes to converge faster. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Overfitting | When a model learns the training data so precisely that it performs well on training examples but poorly on new, unseen examples; a sign the model memorized rather than generalized. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| PAD (Padding) | Special token used to fill shorter sequences in a batch to a uniform length; attention mask is set to 0 at PAD positions so the model ignores them. | [Tokenization](01-foundations/09-tokenization.md) |
| Parallelism | Doing many computations at the same time. GPU parallelism means thousands of identical simple operations on different data elements, all running simultaneously. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Parameter | Any number inside the model that is learned from data during training; includes weights, biases, embedding vectors, and normalization scales. | [Neural Networks](01-foundations/02-neural-networks.md) |
| Pixel Space | The raw representation of an image as pixel values; high-dimensional and redundant; contrasted with latent space where information is compressed. | [Latent Space](01-foundations/07-latent-space.md) |
| Positional Encoding | A mechanism to inject word/token order information into a transformer that otherwise sees all positions simultaneously; common forms are sinusoidal (original) and RoPE (modern). | [Transformers](01-foundations/05-transformers.md) |
| PTQ (Post-Training Quantization) | Quantizing a model after training is complete. No retraining required. The dominant approach for model distribution and inference optimization. | [Quantization](01-foundations/10-quantization.md) |
| QAT (Quantization-Aware Training) | Simulating quantization during training so the model learns to compensate for precision loss. Produces better accuracy than PTQ at the same bit width, but requires a training run. | [Quantization](01-foundations/10-quantization.md) |
| Quantization | The process of representing model weights (and sometimes activations) with fewer bits than their original training format, trading precision for reduced memory and faster inference. | [Quantization](01-foundations/10-quantization.md) |
| Query (Q) | The "what am I looking for?" vector; each token's query is matched against all other tokens' keys to produce attention scores. | [Attention](01-foundations/06-attention.md) |
| Reconstruction | The decoded output of an autoencoder; a measure of how well the latent preserved the original input's information. | [Latent Space](01-foundations/07-latent-space.md) |
| Residual Connection | A connection that adds a layer's input to its output (output = layer(x) + x); essential for training deep networks by providing direct paths for gradient flow. | [Transformers](01-foundations/05-transformers.md) |
| Reverse Process | The generation-time procedure of iteratively applying the denoising model to remove noise step by step; what the trained model learns to do. | [Diffusion](01-foundations/08-diffusion.md) |
| RoPE | Rotary Position Embedding; the positional encoding used in LLaMA and most modern transformers; encodes relative position by rotating Query and Key vectors inside attention. | [Transformers](01-foundations/05-transformers.md) |
| Sampling Steps | The number of denoising steps performed during generation; the primary trade-off lever between speed and output quality. | [Diffusion](01-foundations/08-diffusion.md) |
| Scale Factor | The float value stored alongside quantized weights that maps the integer range back to the approximate float range. One scale per group in group quantization. | [Quantization](01-foundations/10-quantization.md) |
| Scalar | A single number; a 0-dimensional tensor. | [Tensors](01-foundations/01-tensors.md) |
| Scaled Dot-Product Attention | The complete single-head attention operation: softmax(QK^T / sqrt(d_k)) V; the building block for multi-head attention. | [Attention](01-foundations/06-attention.md) |
| Self-Attention | Attention where Q, K, and V all come from the same sequence; each token attends to all tokens in the same sequence, including itself. | [Attention](01-foundations/06-attention.md) |
| SentencePiece | A tokenization library from Google that implements BPE at the byte level; handles any language natively; used by T5, LLaMA, and others. | [Tokenization](01-foundations/09-tokenization.md) |
| Shape | An ordered tuple of integers describing the size of each dimension; e.g., (32, 3, 256, 256). | [Tensors](01-foundations/01-tensors.md) |
| Shared Memory | Fast on-chip memory (per block of threads) used to stage data that multiple threads need. Accessing shared memory is ~100x faster than global memory. Key to writing fast GPU kernels. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Special Tokens | Reserved token IDs that carry structural signals rather than semantic content: BOS (beginning of sequence), EOS (end of sequence), PAD (padding), SEP (separator), UNK (unknown). | [Tokenization](01-foundations/09-tokenization.md) |
| Stride | The number of elements to skip in memory to move one step along a given axis; how the framework maps multi-dimensional indices to flat memory addresses. | [Tensors](01-foundations/01-tensors.md) |
| Subword | A token that represents part of a word; allows the vocabulary to cover rare and unknown words by decomposing them into known pieces. | [Tokenization](01-foundations/09-tokenization.md) |
| T5 Tokenizer | A SentencePiece tokenizer with 32,100 tokens; handles up to 512 tokens; used by LTX-Video for text conditioning via T5 encoder. | [Tokenization](01-foundations/09-tokenization.md) |
| Tensor | A multi-dimensional array of numbers; the generalization of scalars, vectors, and matrices to any number of dimensions. | [Tensors](01-foundations/01-tensors.md) |
| Thread | The smallest unit of GPU execution. One thread runs the kernel code on one element (or one chunk) of data. Thousands run simultaneously. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Timestep | An integer t from 0 (clean) to T (pure noise) indexing the current noise level; passed as input to the denoising model so it knows how noisy its input is. | [Diffusion](01-foundations/08-diffusion.md) |
| Token | A single unit in the tokenizer's vocabulary; may be a character, a subword piece, a whole word, or a special symbol. | [Tokenization](01-foundations/09-tokenization.md) |
| Token ID | The integer index of a token in the vocabulary; what gets passed to the model's embedding table. | [Tokenization](01-foundations/09-tokenization.md) |
| Tokenization | The process of converting raw text into a sequence of discrete tokens (integers) that a model can process. | [Tokenization](01-foundations/09-tokenization.md) |
| Tokenizer | The component that performs tokenization; maps strings to token ID sequences and back; always paired with a specific model's vocabulary. | [Tokenization](01-foundations/09-tokenization.md) |
| Training | The process of adjusting a model's weights based on labeled examples, using a loss function and gradient descent, to minimize prediction error. | [Training vs. Inference](01-foundations/03-training-vs-inference.md) |
| Transformer | A neural network architecture that processes all input positions simultaneously using attention, allowing every element to directly interact with every other element. | [Transformers](01-foundations/05-transformers.md) |
| Transformer Block | The repeating unit of a transformer: LayerNorm -> Self-Attention -> Residual + LayerNorm -> FFN -> Residual. N of these are stacked to form the full model. | [Transformers](01-foundations/05-transformers.md) |
| U-Net | A convolutional neural network architecture with encoder, decoder, and skip connections; the original backbone for diffusion models (used in Stable Diffusion). | [Diffusion](01-foundations/08-diffusion.md) |
| Unified Memory | Apple Silicon's memory architecture where CPU and GPU share a single physical memory pool. No data copying between CPU and GPU. The GPU can use all available system RAM. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| VAE (Variational Autoencoder) | An autoencoder where the encoder outputs a probability distribution (mean + variance) over latent space rather than a single point; trained with both reconstruction loss and KL divergence; produces smooth, interpolatable latent spaces. | [Latent Space](01-foundations/07-latent-space.md) |
| Value (V) | The "what information do I provide?" vector; the actual content that is aggregated using the attention weights. | [Attention](01-foundations/06-attention.md) |
| Vector | A 1-dimensional tensor; a list of numbers. | [Tensors](01-foundations/01-tensors.md) |
| Velocity Prediction | The flow matching model output mode: predict the direction of travel from noise to data; also called "v-prediction" in some frameworks. | [Diffusion](01-foundations/08-diffusion.md) |
| Vocabulary | The fixed set of all tokens a tokenizer knows; tokens outside the vocabulary are split into smaller known pieces. | [Tokenization](01-foundations/09-tokenization.md) |
| VRAM | Video RAM. Dedicated high-speed memory on discrete NVIDIA GPUs, separate from system RAM. Typically 8-80 GB. The hard limit for model size on NVIDIA hardware. | [GPU Computing](01-foundations/04-gpu-computing.md) |
| Weight | A learned parameter tensor inside a layer; the "knobs" that get adjusted during training. | [Neural Networks](01-foundations/02-neural-networks.md) |
